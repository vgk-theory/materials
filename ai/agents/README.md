# agents — гейт проверки материалов раздела `research/`

Три роли-проверяющих для материалов раздела `research/`. Каждая роль — обычный md-файл с инструкцией, которую можно дать **любой LLM** (Claude, ChatGPT, Gemini, Copilot, Cursor, локальная модель) или человеку. Привязки к конкретному инструменту нет: ни специальных полей, ни обязательных плагинов.

| Файл | Роль | Вопрос, на который отвечает | Вердикты |
|------|------|-----------------------------|----------|
| [`math-verifier.md`](math-verifier.md) | математик-физик | верна ли математика и соответствует ли текст первоисточнику | `VERIFIED` · `VERIFIED WITH REMARKS` · `ERRORS FOUND` |
| [`falsifier.md`](falsifier.md) | красная команда | можно ли опровергнуть утверждения материала | `ВЫДЕРЖИВАЕТ` · `ВЫДЕРЖИВАЕТ С ПРАВКАМИ` · `НЕ ВЫДЕРЖИВАЕТ` |
| [`peer-reviewer.md`](peer-reviewer.md) | рецензент журнала | готов ли материал к принятию | `ACCEPT` · `MINOR REVISION` · `MAJOR REVISION` · `REJECT` |

Все три роли работают по единым правилам [`../scientific-method.md`](../scientific-method.md) и ссылаются на них по номерам пунктов.

## Гейт обязателен

Любой материал в `research/` — новый документ, новая секция, правка утверждения, формулы или числа — считается **принятым**, только если прошёл все три роли в фиксированном порядке:

```
материал (редакция N)
  → math-verifier      → отчёт; при ERRORS FOUND правки → редакция N+1 → снова math-verifier
  → falsifier          → отчёт; при НЕ ВЫДЕРЖИВАЕТ правки → редакция N+1 → снова с math-verifier
  → peer-reviewer      → отчёт; при REVISION/REJECT правки → редакция N+1 → снова с math-verifier
  → решение человека: слить pull request
```

Правила гейта:

1. **Порядок не меняется.** Фальсификатор не запускается до вердикта math-verifier, рецензент — до вердикта фальсификатора: каждая роль опирается на отчёт предыдущей и не дублирует её работу.
2. **Одна редакция — один набор отчётов.** В каждом отчёте записывается проверенная редакция: хэш коммита или `sha256` файла. Любое изменение текста после проверки обнуляет отчёты, начиная с первой затронутой роли.
3. **Независимость.** Роль выполняет **не тот** контекст, который писал материал: новая сессия, новый чат или другая модель. Проверяющий читает первоисточники (страницы монографии, скрипты) сам, а не по пересказу в проверяемом тексте, и помечает в отчёте, что читал лично и что знает только по чужому отчёту.
4. **Без материала нет вердикта.** Если роль не смогла что-то проверить (нет данных, нет скрипта), она пишет «не проверено» — не `VERIFIED` и не `ACCEPT`.
5. **Красная команда до счёта.** Если материал содержит расчёт с критериями PASS/FAIL, фальсификатор дополнительно проверяет сами критерии до выполнения расчёта ([`scientific-method.md`](../scientific-method.md), п. 3.4).
6. **Решение — за человеком.** Гейт даёт основания; слияние в `main` выполняет человек после `ACCEPT` (или `MINOR REVISION` с внесёнными правками). Материалы без пройденного гейта могут лежать в репозитории только как черновик со статусом «гейт не пройден» в README раздела.

## Где лежат отчёты

В папке проверяемого раздела: `research/<раздел>/reviews/`. Имя отчёта — объект, роль и дата:

```
research/<раздел>/reviews/<объект>-math-verification-YYYY-MM-DD.md
research/<раздел>/reviews/<объект>-falsification-YYYY-MM-DD.md
research/<раздел>/reviews/<объект>-peer-review-YYYY-MM-DD.md
```

`<объект>` — имя файла или идентификатор правки (например, `formalism`, `axioms-p3`). Статус гейта по каждому документу раздела ведётся в таблице его `README.md`.

## Единая шапка отчёта

Каждый отчёт начинается с одного и того же блока, чтобы отчёты разных моделей и людей были сопоставимы:

```markdown
# <Объект> — <роль>, <дата>

- **Объект:** путь к файлу/секции; редакция: commit <hash> или sha256 <hash>
- **Роль:** math-verifier | falsifier | peer-reviewer
- **Исполнитель:** <модель и версия | человек (роль, без имени, если не хочет указывать)>
- **Входы, прочитанные лично:** список файлов и страниц монографии
- **Известно только по отчётам:** список
- **Предыдущие отчёты гейта по объекту:** список или «нет»
- **Что не проверялось и почему:** список

## Вердикт: <один из допустимых для роли>

<два-четыре предложения: несущее основание вердикта>

## Находки

| № | Серьёзность | Где (файл:строка / стр. монографии) | Что не так | Нарушенный пункт scientific-method.md | Что сделать |
|---|-------------|--------------------------------------|------------|----------------------------------------|-------------|
| 1 | CRITICAL | ... | ... | 2.2 | ... |

## Что подтверждено

<утверждения, проверенные и выдержавшие проверку, со ссылкой на то, как проверялись>
```

Серьёзность: `CRITICAL` — вывод материала не держится; `MAJOR` — вывод держится, но основание неполно или ошибочно; `MINOR` — оформление, точность ссылки, ясность. Любое `CRITICAL` исключает положительный вердикт.

## Как запустить роль в разных инструментах

- **Любой чат (ChatGPT, Gemini, Claude.ai, локальная модель).** Новый чат. Первым сообщением — содержимое файла роли и `scientific-method.md`, затем проверяемый материал и те страницы монографии из `processed/monograph/.../pages/`, на которые он ссылается. Попросить отчёт по шапке выше.
- **Агентные инструменты с доступом к файлам (Claude Code, Cursor, Copilot, Codex и др.).** Новая сессия в корне репозитория. Указать: «Выполни роль `ai/agents/<роль>.md` для `research/<...>` по правилам `ai/scientific-method.md`; отчёт сохрани в `research/<раздел>/reviews/`». Инструмент сам прочитает нужные страницы и скрипты. Если инструмент поддерживает собственный формат субагентов, файл роли можно скопировать в его каталог без изменений; тело инструкции от этого не зависит.
- **Человек.** Читает файл роли как чек-лист и заполняет ту же шапку.

Результат одной и той же проверки у разных моделей может различаться. Расхождение вердиктов — повод для третьего прогона другой моделью или для разбора человеком, а не для выбора удобного вердикта.
