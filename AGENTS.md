# AGENTS.md — контекст проекта для AI-инструментов

Этот файл — единая точка входа для любого AI-инструмента (Claude, ChatGPT, Gemini, Copilot, Cursor и др.), работающего с репозиторием. Прочитайте его целиком перед тем, как что-либо менять. Инструкции нейтральны к поставщику; файлы вроде `CLAUDE.md` только ссылаются сюда.

## 1. О проекте

Репозиторий `vgk-theory/materials` — научные материалы теории Виктора Григорьевича Катющика (VGK): труды автора и их продолжение силами сообщества единомышленников.

Виктор Григорьевич — автор монографии «Гравитационное взаимодействие, основы космологии». Сам автор определяет её материалы как «научную констатацию» — «строгое научное построение, не опирающееся ни в одном из своих разделов на какие либо гипотезы». Помимо монографии, теория изложена в большом количестве авторских видео на YouTube. Сообщество последователей сохраняет эти труды и продолжает развивать теорию.

Краткие биографические сведения об авторе: [`author.md`](author.md).

Репозиторий служит для:

- хранения оригинальных материалов автора;
- хранения производных текстов, полученных с помощью AI (монография в md, транскрипты видео);
- публикации анимаций (интерактивных на JavaScript и пассивных gif), которые открываются прямо в браузере;
- хранения презентаций и новых исследований последователей;
- параллельной работы нескольких людей с AI-инструментами разных поставщиков.

Сайт (GitHub Pages, ветка `main`, корень репозитория): `https://vgk-theory.github.io/materials/`.

## 2. Содержание и формулировки

- Фокус проекта — научное содержание теории. Биографические сведения об авторе собраны в одном файле, [`author.md`](author.md); в остальных материалах их не дублировать.
- Положения теории излагать так, как они сформулированы автором, со ссылкой на источник (страница монографии, видео). Не пересказывать «своими словами» там, где нужна точность.
- **Не сочинять** содержание теории, термины, формулы, названия разделов и факты биографии. Если сведений нет в материалах репозитория — оставить помеченную заглушку (`TODO`) для заполнения людьми.
- Язык документации — русский (пока сообщество не решит иначе).

## 4. Структура репозитория

Целевая структура. Часть файлов ещё не создана — перед работой проверяйте фактическое состояние.

```
/
├── README.md               — что это за проект, как устроен, как участвовать
├── AGENTS.md               — этот файл: инструкции для AI-инструментов
├── CLAUDE.md               — одна строка: @AGENTS.md
├── author.md               — биографические сведения об авторе
├── CONTRIBUTING.md         — правила работы для участников
├── index.html              — главная страница сайта (Pages)
├── view.html               — показ на сайте отдельных md-документов: view.html?file=<путь>
├── .nojekyll               — отключает Jekyll-обработку на Pages
├── sources/                — оригиналы автора, без изменений
│   ├── monograph/          — труды автора: <труд>.pdf; README.md — их список (страница «Монография» на сайте)
│   └── videos/             — videos.md: название, ссылка, дата, наличие транскрипта
├── processed/              — производные от оригиналов (в т.ч. через AI)
│   ├── monograph/
│   │   └── <труд>/         — имя папки совпадает с именем исходного файла
│   │       ├── README.md   — сведения о труде и об обработке
│   │       ├── pages/      — постраничный текст: page-NNNNN.txt (номер файла = номер страницы)
│   │       └── chapters/   — текст в md по главам (если есть)
│   └── transcripts/        — расшифровки видео, один md на видео
├── animations/
│   ├── index.html          — каталог анимаций (читает catalog.json)
│   ├── catalog.json        — данные каталога; пересобираются скриптом build-catalog.py
│   ├── _template/          — шаблон папки явления
│   ├── shared/             — общие стили и библиотеки (vendor/: marked, KaTeX)
│   └── <topic>/            — тема (раздел теории); README.md задаёт её название
│       ├── <subtopic>/     — подтема (если нужна), вложенность не ограничена
│       └── <phenomenon>/   — явление
│           ├── index.html          — интерактивная версия (если есть)
│           ├── script.js
│           ├── <phenomenon>.gif    — пассивная версия (если есть)
│           ├── preview.gif|png     — только если основной gif тяжёлый
│           ├── README.md           — описание явления
│           └── src/                — исходники генерации gif (если есть)
├── presentations/          — презентации
├── research/               — новые материалы последователей
└── ai/
    ├── prompts/            — переиспользуемые промпты
    └── glossary.md         — терминология теории
```

В каждом каталоге есть `README.md` с его назначением и локальными правилами — читайте его перед работой в каталоге.

## 5. Обязательные правила

1. **Оригиналы неприкосновенны.** Файлы в `sources/` не изменяются, не переименовываются и не «улучшаются». Допускается только добавление новых оригиналов. Любая обработка лежит в `processed/` и ссылается на исходник.
2. **Авторство помечается явно.** Всегда должно быть понятно, что написано автором теории, что создано последователями, а что сгенерировано AI. Если текст или анимацию создали вы — укажите это (front matter, README явления).
3. **Только относительные пути** во всех html/md (`../shared/lib.js`, а не `/animations/shared/lib.js`), чтобы сайт работал при любом имени репозитория и пережил перенос.
4. **Никаких внешних CDN.** Библиотеки, стили и шрифты хранятся локально в `animations/shared/`, чтобы анимации работали долгие годы.
5. **Никаких сборочных инструментов** (npm-сборка, фреймворки). Сайт — набор статических файлов.
6. **Видео в репозитории не хранятся.** Они остаются на YouTube; в репозитории — ссылки, метаданные и транскрипты. Файлы больше 50 МБ не добавлять без согласования с людьми.
7. **Анимации организованы по темам и явлениям, а не по формату.** Темы могут быть вложенными (`animations/<topic>/<subtopic>/<phenomenon>/`). Новые темы и подтемы не заводить без согласования с участниками.
8. **Не перезаписывать существующее.** Перед созданием файла проверить, нет ли его уже.

## 6. Соглашения

### Именование

- Латиница, строчные буквы, дефисы вместо пробелов: `wave-interaction`.
- Без дат и версий в именах (история хранится в git).
- `index.html` в папке явления всегда означает интерактивную версию.
- Gif носит имя явления: `wave-interaction.gif`. Несколько пассивных версий различаются суффиксом: `wave-interaction-side-view.gif`.

### Папка явления

- Папка считается явлением, если в ней есть `index.html` или gif; всё, что выше, — темы и подтемы. Название темы в каталоге берётся из первого заголовка её `README.md`.
- Относительные пути в `index.html` явления зависят от глубины вложенности: на каждый уровень подтемы добавляется одно `../`.
- Явление, у которого есть только gif, тоже оформляется папкой. Когда появится интерактив, в неё добавляется `index.html`, ссылки не ломаются.
- После добавления или удаления анимации пересобрать каталог: `python3 animations/build-catalog.py`. Вручную `catalog.json` не править.
- Если автор материала неизвестен (например, запись взята из публичных источников), так и указывать: «неизвестен». Авторство не домысливать.
- README явления содержит: что показано; ссылку на главу монографии и/или видео; перечень имеющихся версий; автора анимации; пометку об участии AI. Gif вставляется прямо в README.

### Производные тексты (`processed/`)

Каждый md-файл начинается с front matter:

```yaml
---
source: ../../sources/monograph/<файл>      # или ссылка на YouTube
source_type: monograph | video
processed_by: <инструмент/модель или человек>
processed_date: YYYY-MM-DD
reviewed_by_human: false
---
```

`reviewed_by_human` меняет на `true` только человек после проверки.

### Труды автора (`processed/monograph/`)

- Один труд — одна папка `processed/monograph/<труд>/`, названная так же, как исходный файл в `sources/monograph/`.
- Постраничный текст лежит в `pages/page-NNNNN.txt`; номер файла совпадает с номером страницы исходного PDF. Сведения об источнике и обработке (front matter) — в `README.md` папки труда.

### Транскрипты

Один файл на видео; имя файла из идентификатора или краткого названия видео; во front matter дополнительно `video_url` и `video_title`.

### Сайт (GitHub Pages)

- На сайте показываются только: каталог анимаций, презентации, список трудов автора с оригиналами в PDF (`sources/monograph/README.md`), сведения об авторе (`author.md`) и правила участия (`CONTRIBUTING.md`). Остальные md-файлы — рабочие материалы: на сайте на них не ссылаются, их читают в репозитории.
- Оформленный показ md-файлов — `view.html?file=<путь от корня>`; он открывает только документы из списка `PUBLIC` в `view.html` и отрисовывает формулы LaTeX (`$...$`, `$$...$$`). Чтобы показать на сайте новый документ, его добавляют в этот список.
- В самих md-файлах ссылки остаются обычными относительными: просмотрщик переводит их на себя, а ссылки на рабочие файлы — в репозиторий на GitHub.
- Оформление сайта задано в `animations/shared/style.css`: тёмная «звёздная карта», цвета и шрифты — переменными в начале файла. Новые страницы используют эти переменные и классы, а не собственные цвета и шрифты; шрифты лежат локально в `animations/shared/fonts/`.
- Общую шапку с навигацией и подвал добавляет `animations/shared/site.js`; новые html-страницы подключают его (`<script src="<путь>/animations/shared/site.js"></script>`). Пункты меню и адрес репозитория правятся в этом файле.

### Работа с git

- Ветка на задачу, pull request, ревью перед слиянием в `main`.
- Не коммитить и не пушить без явной просьбы человека.

## 7. Как искать в монографии

Текст монографии большой. Не читайте его целиком и не открывайте PDF — переходите к нужному месту точечно:

1. **Поиск по словам** — по каталогу `pages/` нужного труда, с номерами строк:
   `grep -rn "телесный угол" processed/monograph/<труд>/pages/`
   Слова ищите по основе, без окончания (`равновеси`, а не `равновесие`): в тексте встречаются разные формы.
2. **Переход по номеру страницы** — имя файла соответствует странице монографии: страница 38 — это `pages/page-00038.txt`.
3. **Чтение** — открывайте только найденные страницы (одна страница — 2–7 тысяч знаков) и при необходимости соседние: мысль может переходить со страницы на страницу.
4. **Ссылка** — в ответах и производных материалах указывайте труд и страницу: «Гравитационное взаимодействие, основы космологии», стр. 38.

Формулы на части страниц записаны в LaTeX (`$F = -G \frac{mM}{r^2}$`).
