# corrections — правки к формализованному изложению теории

Слой **работы над теорией**, отделённый от её изложения. Раздел
[`formalized-theory/`](../formalized-theory/README.md) фиксирует, что говорит монография
(постулаты, определения, формулы с провенансом по страницам, оценка составителя). Здесь
лежат **правки** — предложения изменить или дополнить это изложение: уточнить область
применимости постулата, выставить статус выводу автора, добавить формулу или строку
статуса. Правка не меняет документы `formalized-theory/` сама: до **материализации**
(отдельного pull request с гейтом раздела целиком) канон о ней не знает. Так
читатель всегда видит две вещи раздельно: **что в монографии** и **что с этим сделали
последователи**.

## Структура

```
research/corrections/
  README.md                    — этот файл: концепция, соглашения, индекс правок, статус гейта
  reviews/                     — отчёты гейта по правкам: PK-<N>-<роль>-<дата>.md; archive/
  PK-<N>-<slug>/               — одна правка = одна папка
    PK-<N>.md                  — карточка правки (полный текст, автономный)
    sims/                      — скрипты расчётов и их результаты (_*.json), если есть
```

Всё, что нужно правке, лежит в её папке. Отчёты гейта — в `reviews/`, по шапке
[`ai/agents/README.md`](../../ai/agents/README.md).

## Соглашения

- **Идентификатор** `PK-<N>` (латиница; «PK» — правка к канону), номер не переиспользуется;
  папка `PK-<N>-<slug>/`, карточка `PK-<N>.md`.
- **Front matter** карточки — как в `formalized-theory` (`source`, `source_type: monograph`,
  `document: correction`, `authors`, `processed_by`, `processed_date`, `reviewed_by_human`)
  плюс `id`, `slug`, `revision`, `target` (документы канона, которые правка меняет),
  `canon_revision` (commit и sha256 редакции канона, против которой написана дельта),
  `status` (см. шкалу ниже).
- **Содержание карточки**: что утверждает первоисточник и где (цитаты по страницам);
  почему нужна правка (анализ с провенансом `[ИСТОЧНИК стр. N]` / `[ВЫВЕДЕНО]` /
  `[ПРОБЕЛ]`); **формулировка правки**; что канон уже содержит (чтобы не дублировать);
  **материализация** — дельта: для каждой вставки дословный якорь в текущей редакции канона
  и дословный текст вставки **в формате канона** (провенанс на каждом утверждении, внешние
  ссылки «внешнее, ссылка: …» со строкой переносимости по п. 3.1, несущие числа — командой
  проверки, статусы только по шкалам канона и `scientific-method.md` §4, критерий провала у
  каждого вывода); что не правится и почему; наследуемые стены (п. 3.6); проверяемость;
  процесс.
- **Правила раздела `research/`** действуют полностью: [`ai/scientific-method.md`](../../ai/scientific-method.md)
  (включая §4 — оценка утверждений теории в её собственных дефинициях) и гейт трёх ролей
  [`ai/agents/README.md`](../../ai/agents/README.md). Единица проверки — правка целиком:
  карточка, её скрипты и документы канона, которые она меняет, в одном контексте; один отчёт
  на роль. Своему тексту `VERIFIED`/`ACCEPT` не ставится.
- **Отзыв** (п. 1.8): отозванное утверждение правки остаётся в карточке с датой и причиной;
  производные (числа, скрипты, статусы) правятся в том же изменении.
- **Без внутренних ссылок**: карточка автономна — не ссылается на материалы вне этого
  репозитория, на отчёты прежних редакций, на личности.

## Статусы правки (`status` во front matter и в индексе)

| Статус | Значение |
|---|---|
| `proposed` | карточка написана, гейт не пройден или прерван находкой CRITICAL |
| `gate-passed` | три роли пройдены (peer-reviewer `ACCEPT` или `MINOR REVISION` с внесёнными правками); материализация не выполнена |
| `applied` | дельта внесена в `formalized-theory/` (указать commit), раздел `formalized-theory` прошёл гейт с ней |
| `withdrawn` | правка отозвана (дата, причина — в карточке) |

Переход `gate-passed → applied` — решение человека (правило 6 гейта); до него документы
канона правку не упоминают.

## Материализация

1. Дождаться слияния в `main` текущей редакции раздела `formalized-theory` (любая правка его
   документов обнуляет пройденный им гейт с первой затронутой роли).
2. Сверить якоря дельты против того коммита `main`, в который она войдёт (редакция могла
   сдвинуться относительно `canon_revision`).
3. Отдельный pull request: вставки по дельте в документы канона (без идентификатора правки и
   маркеров в тексте канона — история правки остаётся в этом разделе и в git), сопутствующие
   правки README раздела (нумерация формул, статус гейта), перенос прежних отчётов раздела в
   `reviews/archive/`.
4. Гейт раздела `formalized-theory` целиком по правилу 7; после прохождения — `status: applied`
   с commit в карточке и в индексе.
